# 台风影响研判系统 · 构建任务书 v2

> v1 的修正说明:v1 把重心错放在网页抓取上,忽略了 ECMWF 已全面开放的机器可读台风路径产品;未定义预测目标变量;未要求预报存档;共识度指标缺少校准。本版全部修正。

---

## 0. 定位声明(先读这一段,它决定后面所有设计)

### 0.1 这个系统预测什么

台风路径由大尺度环境流场决定。预测路径本质上等于预测未来一周的全球流场,这只能由全球数值模式 + 资料同化 + 超算完成。本系统**不自建路径预报模式**。

本系统的预测能力分三层,按顺序建设:

| 层 | 能力 | 状态 |
|---|---|---|
| **A. 多源集合共识** | 汇聚各机构与各模式预报,做集合共识与不确定性量化。多模式集合平均通常优于任一单一来源,这是有真实技能的预测 | 第一阶段交付 |
| **B. 性能加权与影响降尺度** | 基于自建的预报误差库,对各来源做性能加权与偏差订正;建立上海本地影响转译模型 | 需 1-2 个台风季数据积累 |
| **C. 自跑 AI 气象模型** | Pangu-Weather / GraphCast / FuXi / FengWu / AIFS 权重公开,可自行推理 | 可选实验分支 |

参照:香港天文台已业务化使用上述五个 AI 模型构成的集合做台风路径预报,权重依据各模型上一年度的路径预报表现确定。Layer B 的做法与国家级气象机构一致,不是妥协方案。

### 0.2 这个系统真正的价值不在路径精度

上海台风研究所的混合模式在 96 小时内的路径与强度预报优于所有 AI 气象模型。本系统不试图在路径精度上竞争。

**唯一不可替代的价值是:把气象预报翻译成本单位的行动决策——这周的活动要不要动、什么时候必须拍板。** 所有设计取舍以此为准。当"更精确的路径图"与"更清楚的决策结论"冲突时,选后者。

### 0.3 已知的能力边界(必须在页面上显式声明)

- AI 气象模型普遍显著低估台风强度
- AI 模型在急转弯路径个例上表现明显弱于传统数值模式
- 集合发散度是不确定性的代理量而非等价物;各模式误差相关,存在"一致地错"的情形
- 超过 120 小时,各机构不发布确定性路径,本系统同样不得绘制

## 1. 硬约束(违反即返工)

1. **禁止编造数据源。** 任何数据源在编写解析代码之前,必须先实际调用并在审计报告中粘贴真实返回内容的前若干行(原始字节或解码结果)。无法出示者一律从方案中删除,不得以"接口可能存在"的方式写入代码。
2. **不得使用官方预警的词汇与配色。** 蓝黄橙红是上海市气象局的法定预警信号。本系统内部研判等级用「关注 / 警戒 / 行动」,配色避开预警色系。
3. **每屏及每份导出物固定标注**:「内部研判参考,不构成气象预报。权威信息以上海市气象局、上海市防汛指挥部发布为准。」
4. **D-5 以外不绘制确定性路径线。** 仅展示集合概率分布、影响概率与情景描述。
5. **抓取失败显式标注**,不用历史值填充,不做插值伪装。
6. **强度数值必须标注来源与风速平均时距**,不换算不得并列比较。
7. **从第一次运行起,每一次抓取到的预报必须原样存档。** 此能力不可追溯补建,是 Layer B 的唯一前提。

## 2. 数据源(骨干已定,不要从抓取开始)

### 2.1 骨干源:ECMWF Open Data(优先级最高,先打通这一个)

ECMWF 自 2025 年 10 月起将实时产品目录以 CC-BY-4.0 全面开放,含热带气旋路径专门产品:

- Python 包:`ecmwf-opendata`
- ENS 集合路径:`stream="enfo"`, `type="tf"`
- 确定性路径:`stream="oper"`, `type="tf"`
- AIFS 集合:`model="aifs-ens"`;AIFS 确定性:`model="aifs-single"`
- 格式 BUFR4,需 BUFR 解码库(eccodes)
- 注意:台风路径产品**仅在有台风存在或被预报时才提供**,平静期无数据是正常状态,不是故障
- 直连门户有并发连接数限制,数据在 AWS / Azure / GCP 有镜像,应实现镜像回退

这一个源即可提供 51 个集合成员路径 + AI 模型路径 + 确定性路径,合规、机器可读、免费。**它替代了 v1 方案中大部分爬虫工作,必须最先打通。**

GitHub Actions 运行在境外节点,与开发者在上海本机的网络可达性是两套完全不同的结果:境内源可能拒绝境外 IP,境外源本机可能不通。

## 4. 预测目标定义(在写评分算法之前必须完成)

**没有标签就没有校准,没有校准评分就是拍脑袋。** 先定义系统到底在预测什么。

建议目标变量(可调整,但必须选定并写死):

- **主目标**:上海市气象局是否发布台风或暴雨橙色及以上预警(二分类)
- **辅目标一**:上海全市面雨量过程累计是否超过阈值
- **辅目标二**:是否出现停工停课或大型活动普遍取消
- **辅目标三**:黄浦江潮位是否超警戒

三档研判等级与目标变量的对应关系写入 `targets.md`,并说明每档对应的概率区间。

## 5. 核心算法

### 5.1 强度归一化(优先实现)

JMA 用 10 分钟平均风,JTWC 用 1 分钟,中央气象台用 2 分钟。展示前统一换算,系数写入配置文件(1 分钟风 ≈ 10 分钟风 × 1.14)。每个数值旁标注原始来源与原始口径。

### 5.2 集合共识与不确定性(核心)

- 计算多来源共识路径(等权平均作为基线;Layer B 阶段改为性能加权)
- 计算集合离散度
- **强制要求:离散度不得单独作为确定性指标展示。** 必须同时叠加该预报时效的历史误差统计(误差圈半径),并在文案中明确"低离散度不等于高确定性,各模式存在相关误差"
- 离散度到实际误差的映射关系,在积累足够样本后用历史数据校准;校准完成前,页面上标注该指标为"未校准,仅供参考"

### 5.3 上海影响判据

上海的风险不是"是否登陆",而是**风、暴、潮、洪四碰头**:本地暴雨 + 风暴增水 + 天文大潮 + 太湖流域洪水下泄。

输入变量:

1. 最近点距离(DCA)与到达时刻
2. 最近时刻强度,7 级 / 10 级风圈是否覆盖上海
3. 上海所处象限(东侧右半圆以大风增水为主,西北侧以暴雨为主)
4. 移动速度(慢速滞留使累计雨量激增)
5. 与朔望大潮的时间叠合度
6. 是否有西风槽或冷空气配合(远距离暴雨、变性加强)
7. 前期累计降水与土壤饱和度

阈值全部写入配置文件。**在完成第 7 节的回算校准之前,所有阈值标记为"初始猜测值",页面显著标注系统处于未校准状态。**

### 5.4 历史类比检索

用轨迹相似度(DTW 或 Fréchet 距离)从历史最佳路径库检索最相似历史台风,输出相似度分值,并调出那次上海的实际影响档案(过程雨量、极大风、最高潮位、是否停工停课、主要灾情,先覆盖近 20 年)。

## 6. 预报存档(与主功能同等优先级)

每次运行,将所有来源的**当次预报原文**按 `archive/YYYYMMDD/HHz/{source}/` 存档,保留原始格式。

存档内容至少包括:预报发布时间、起报时刻、各时效预报位置与强度、来源标识。

这是 Layer B 的唯一前提。第一个台风季不存档,第二年就没有误差库可建,性能加权与偏差订正永远无法实现。

---

## 7. 回算与校准(v1 的方案是错的,按本节执行)

### 7.1 前视偏差警告

用当前可抓取的历史数据做回算是**伪回算**——拿到的多是事后最佳路径,而非当时发布的预报。必须使用当时的预报存档(JTWC ATCF a-deck、TIGGE)。无法取得真实历史预报的来源,不参与回算。

### 7.2 样本量要求

两个个例没有统计意义。回算样本至少覆盖近 10-15 年所有对上海产生影响的台风(量级约数十例),并在报告中明确说明:该样本量下阈值校准存在过拟合风险,结论为初步。

### 7.3 产出

`backtest.md`:各时效的路径误差分布、研判等级与实际目标变量的混淆矩阵、离散度与实际误差的相关性、阈值敏感性分析。

| 时效 | 信息性质 | 建议动作 |

| D-0 | 实况监测 | 执行与现场安全 |
